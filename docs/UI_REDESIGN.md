## 痛點與修正目標

| 現況 | 使用者成本 | 改版目標 |
|---|---|---|
| 大標、英文眉題與空白佔首屏約三分之一 | 看不到這個 demo 可以做什麼 | 簡短產品標頭；首屏直接進入工作區 |
| 左側長表單，手機約一屏後才見波形 | 先理解參數才知道價值 | 簡單樣本選擇與單一主要動作；先見訊號與反應 |
| 睜眼／閉眼切換只載資料，還要再按分析 | 反應斷裂、容易誤以為沒有變化 | 意圖明確的樣本切換觸發真實分析；逐步顯示載入、品質、推論狀態 |
| 波形只有三條線，缺獨立通道標籤、時間尺及片段上下文 | 缺乏可信儀器感，也難知道分析哪段 | 清楚時間尺、O1/Oz/O2 標籤、選區、游標；顯示單位與可讀振幅參考 |
| 小眼形只改高度，結果與數值分散 | 不易理解動作是由什麼控制 | 單一視覺反應區，緊鄰閉眼任務分數與狀態；只映射實際後端輸出 |
| 小字 pre 與長段警語預設全露 | 認知負擔與工程原型感 | 品質與必要限制靠近結果；完整基線、矩陣、門檻放可展開證據區 |
| 品質失敗與尚未分析不夠突出 | 可能把過期結果當新結果 | 有明確 ready/loading/analyzing/accepted/rejected/error/stale 狀態；拒絕後不留有效分數 |
| 手機只是卡片依序堆疊 | 核心回饋太遠、長距離滾動 | 核心波形／反應優先；設定精簡、進階展開，主要動作容易觸及 |

## 不依賴風格的互動架構

1. 首次進入顯示簡短任務：「播放公開錄製，分析一段訊號，再試試雜訊。」不加登入、導覽頁或大 modal。
2. 主要工作區包含樣本來源／睜閉眼切換、真實波形、四秒片段、分析動作與結果反應。預設仍可用 S008 12–16 秒，清楚註明這是已知品質通過的展示片段。
3. 進階設定展開受試者與 4／8 秒；改變片段時標示舊分析已失效。使用者滑動時不能繼續展示舊數值為當前結果。
4. 品質通過才展示模型分數與介面動作；人工雜訊真的污染分析副本，拒絕時停用分類並具體指出通道與原因。提供「恢復原始訊號」一步返回。
5. 結果區顯示來源、選段與任務分數；完整頻帶、峰對峰、25/60 測試覆蓋率、88.89% 僅通過窗的基線、有效訓練受試者及矩陣都保留在審閱證據。
6. JSON 匯出保持可追溯；專家摘要可展開閱讀，不用人工聊天稿代替運算。

## 實作約束

- 保持 FastAPI API、模型、資料、quality 規則與 subject split 不變。只調 UI 組織及前端互動。
- 過期 HTTP 回覆用 request generation 防護；載入時停用依賴資料的動作。所有數值／場景只由同一後端回應更新。
- Canvas 只有尺寸變更時調整 backing store，播放時不逐幀重設尺寸；使用時間標籤與通道標籤，不加假資料。
- 尊重 prefers-reduced-motion；沒有閃爍、刺激、音訊或醫療效果暗示。必要狀態不只靠顏色。
- 桌機至少驗證 1440×1000、1280×900；手機 390×844 與 360×800。重要文字避免小於 14px；鍵盤 focus 清楚、控制項有可存取名稱。
- 視覺方向由父端參考圖定稿；依最新方向改用暖白／深墨／teal 的 OG 品牌。避免卡片拼貼、泛用 KPI 格子、假腦掃描、裝飾性頻譜。

## 已實作與驗收

- 主畫面為可縮放 canvas 風景視窗＋實際波形，右側集中樣本、品質與模型分數，底部為真正錄製時間軸。視窗開合只映射後端 closed_probability；背景不是腦影像或臨床視覺化。
- 首次一鍵開始會回放與分析；後續來源／睜閉眼樣本切換直接分析。每個載入／推論使用 generation 防止舊回應覆蓋新選擇，測試刻意保留一個真實舊回應再釋放，確認不會覆寫。
- 樣本／片段變更立即清除分數與匯出；品質拒絕時分數與填條立即清空、動態景觀暫停，人工脈衝標示、通道原因與一步恢復可見。波形超出 ±100 µV 範圍有 △ 標記，不假裝資料不存在。
- 手機把時間軸移到波形下方，避免控制項被完整設定區擋住；主視窗也有暫停／回放。完整證據與進階設定只在需要時展開。
- 1440×1000、1280×900、390×844、360×800 測試通過；無水平溢出。公開／合成自動推論、場景幾何變化、雜訊拒絕與恢復、JSON 真實來源、時間軸、競態、reduced-motion 均通過。模型／API 六項測試維持通過。
